   ```powershell
   docker compose --env-file .env.docker.local build
   docker compose --env-file .env.docker.local up -d postgres migrate executor api web
   ```

3. При выключенных вызовах проверить проект, выбранные источники, assessments/страницу и текущий Run через UI/API. Не запускать новый Run вместо сохранённого. Не использовать `.git/stage5_live.py setup`: временный локальный скрипт способен вернуть старые маленькие бюджеты. Временные скрипты из `.git` не являются частью поставки.
4. После поручения возобновить платную работу включить вызовы в env, пересоздать api/worker, затем выполнить `resume` для указанного Run. PM тоже может обрабатывать очередь, поэтому проверить ожидающие сообщения перед включением.

   ```powershell
   docker compose --env-file .env.docker.local up -d --no-deps --force-recreate api worker
   $projectId = '9b408ca2-fd6b-418a-96d0-c5c49a8faef2'
   $runId = 'ed77b9a6-0431-4ee6-847a-a0bbe5ef24ef'
   Invoke-RestMethod -Method Post -Uri "http://localhost:8080/api/projects/$projectId/runs/$runId/control" -ContentType 'application/json' -Body '{"action":"resume"}'
   ```

5. Довести независимую проверку всех критериев, публикацию итогового отчёта и завершение Run. Проверить сохранность jobs и результата после перезапуска. Если исходное время закончится, зафиксировать исход честно и подготовить новую итерацию с точными источниками и согласованной политикой; не менять исходный frozen scope в БД вручную.
6. Обновить документ этапа 5 реальным исходом, идентификаторами опубликованной версии и расходами с разделением подтверждённых/неизвестных запросов. Затем брать следующий этап roadmap.

Для изменения бюджета предусмотрен `PUT /api/projects/{project}/runs/{run}/budget` с `api_budget`, `expected_revision`, новым UUID `client_id`. В текущем запуске 150 RUB уже установлены; повторная операция без необходимости не нужна. `resume` выполняется отдельно.

## Передача на другую машину

Git содержит исходники и документацию. Ключи, `.env*`, PostgreSQL, checkpoints, datasets, артефакты и локальные backup **не передаются push**. Для продолжения именно этого Run нужен согласованный backup текущей БД и uploads/runs volumes вместе с исходным `WORKSPACE_ENCRYPTION_KEY`, переданный отдельно защищённым способом. Не публиковать их в репозитории. Без такого переноса новый разработчик сможет воспроизвести сценарий на синтетическом CSV, но не возобновить локальный Run по его UUID.

На чистой установке использовать bootstrap и [DEPLOYMENT.md](DEPLOYMENT.md). Для backend-тестов требуется отдельная БД с суффиксом `_test`: тесты пересоздают её схему. Не направлять `TEST_DATABASE_URL` на рабочую БД.

У репозитория есть branch-policy CI: PR в `dev` ожидает `feature/*`, `fix/*`, `chore/*` и перечисленные служебные префиксы, тогда как текущая сохранённая ветка называется `codex/*`. Перед будущим PR создать подходящую ветку на том же коммите либо отдельно согласовать изменение политики; в рамках этой передачи CI и правила веток не менялись.
