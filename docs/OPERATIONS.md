# Управление исследованиями

Проект содержит несколько Run. Каждый фиксирует задачу, файлы с SHA256, провайдера/модель, политику и тариф. Новый запуск не затирает историю.

Повторная загрузка файла с тем же именем создаёт новый вход; следующий запуск берёт последнюю версию каждого имени. Предыдущие Run сохраняют свои копии. Проект можно переименовать, изменить задачу для будущих запусков, архивировать и удалить через меню рядом с заголовком. Архив и удаление требуют завершения активного запуска; удаление также ждёт текущий ответ PM и убирает checkpoints проекта.

- queued: ждёт активный слот worker.
- running: агенты и вычисления работают.
- pausing: новые действия запрещены, текущие завершаются.
- paused: состояние сохранено, активное время остановлено.
- finalizing: пользователь запросил итог; проверка и доставка в пределах оставшегося времени, не более десяти минут.
- stopping: отмена активных действий.
- completed / stopped / failed: завершённый запуск; можно создать новый.
- recovering: восстановление того же запуска после перезапуска worker.

Пауза может ждать текущий API-запрос или обучение. «Остановить» отменяет активную работу. Отправленный провайдеру запрос может тарифицироваться после отмены. Артефакты сохраняются.

Явная пауза останавливает активный бюджет после завершения текущих действий. Аварийный простой не расширяет дедлайн. Продолжение восстанавливает сессии и смещает временные планы. Длительность запуска задаётся в настройках проекта.

## PM и поручения

PM читает факты проекта и передаёт поручения только техлиду. Состояния: ожидает PM, в очереди, доставлено, принято/отклонено/выполнено с объяснением. Доставка не означает выполнения. Без активного запуска поручение ждёт запуска; на паузе — продолжения. Кнопки lifecycle используют прямой управляющий канал и не ждут решения LLM. После включения модели будут обработаны pending-сообщения. Прерванный ответ PM помечается ошибкой; повтор инициируется пользователем с проверкой сохранённого поручения.

## Восстановление

PostgreSQL advisory lock допускает одного владельца worker. Executor хранит launch intent, токен и проверяемую идентичность процесса. Потерянный HTTP-ответ не означает повторного обучения. Неопределённое задание становится interrupted, его артефакты сохраняются, новое решение принимает агент.

LangGraph сохраняет шаги сессий в PostgreSQL; инструменты сверяют отдельные квитанции. Неизвестные побочные эффекты не повторяются автоматически. При перезапуске незакрытые денежные резервы учитываются консервативно.

Успешный Python-процесс и проверенный ML-кандидат — разные вещи. Evaluator проверяет кандидата отдельно. История Run позволяет скачать исходники, логи, события и проверенную публикацию.
