# Четвёртый этап: аналитические результаты и отчёты

Добавлен вертикальный путь: выполненный расчёт → неизменяемый результат → независимая проверка → версия отчёта → аналитическое завершение. Модель Qwen не вызывалась. Проверки используют PostgreSQL и настоящие локальные stdlib Python-процессы; качество автономного выбора методов/графиков моделью и запуск через удалённый executor требуют следующего контролируемого прогона.

## Результаты и доказательства

`register_result` сохраняет dataset/table, metric, finding, chart или report. В первой версии dataset — ограниченное подготовленное представление, а не новое хранилище произвольного большого датасета. Численные результаты требуют собственного успешного source job и JSON внутри его JOB_DIR. Редактор может собирать chart/report JSON в своей рабочей области по существующим результатам.

Сохраняются автор, назначение, source job, версия Run/итерации, снимок входов, SHA256, зависимости, предыдущая ревизия и замороженный файл. Новая версия не изменяет старую; устаревшая базовая версия отклоняется. SQL-триггер `0006` защищает artifact, result_revision, assessment, page_revision и delivery_contract. Эффект и квитанция инструмента фиксируются атомарно; файлы без ссылок после отката не становятся результатами.

Лимиты: JSON до 1 MiB, таблица до 500 строк, 30 столбцов и 5000 ячеек, до 200 символов в ячейке; отчёт до 20 блоков. Предпросмотр не выдаётся за полные исходные данные. Для таблиц/метрик обязательны описание выборки и sample_size, для метрик — единица. Отсутствующие значения сохраняются явно. Большие расчёты агент должен свести в подготовленное представление.

## Проверка

Evaluator запускает собственный успешный job после регистрации точной ревизии. Verification JSON содержит result_id, SHA256, status, checks и conclusion. Verified требует непустого набора успешных проверок; refuted — хотя бы одной неуспешной. Запрещена проверка собственного результата, source job или транзитивно собственного доказательства.

Это структурная проверка полномочий и происхождения, не автоматическое доказательство научной истинности. Ответственность evaluator — независимый пересчёт из оригиналов, проверка знаменателя, фильтров, единиц и ограничений вывода.

При изменении файла результата или доказательства проверки статус становится broken. Новая проверка исправного исходного результата может заменить повреждённое свидетельство. Опровержение обязательного блока снимает текущую публикацию, сохраняя прежнюю PageRevision и её статусы на момент публикации. Старые выводы не переписываются.

## Отчёт и завершение

В GoalSpec добавлен research_type: auto/analysis/ml/mixed. PM может выбрать его при подготовке цели; пользователь — при редактировании. Техлид фиксирует declare_delivery с видом работы и конкретными критериями. Явный вид исходной цели нельзя подменить.

Редактор составляет report из ссылок на фиксированные ревизии. Он может сохранить черновик, но не присвоить approval. Итоговую страницу публикует техлид: все обязательные блоки, их зависимости и сам отчёт должны иметь допустимые независимые assessments. Проверка отчёта явно рассматривает каждый объявленный критерий.

- Analysis завершается опубликованным проверенным отчётом; submission.csv не нужен.
- ML сохраняет прежний путь evaluator-approved предсказаний.
- Mixed требует обоих результатов.
- Inconclusive сохраняется отдельно: ограничение данных/метода должно иметь независимое свидетельство. Оно не отображается как доказанный положительный вывод.

Закрытие команд, отсутствие незавершённых jobs, deadline, бюджет и pause/stop/recovery сохраняются. Старые ML-кандидаты доступны через совместимое представление в индексе результатов; их прежний протокол проверки не заменяется новым.

## Интерфейс и API

На обзоре проекта находится отчёт с выбором Run и версии страницы. Показываются метрики, таблицы с постраничным просмотром, выводы и графики bar/line/scatter. ChartSpec ссылается на таблицу и её столбцы, содержит подписи осей и caption. Произвольный HTML/JS, внешние данные и код спецификацией не допускаются. Ошибка блока локализуется.

Под блоком доступны версии источников, SHA256, автор, source job, исходный JSON, код/логи и независимая проверка. При замене входного файла результат помечается относящимся к прежней версии. Историческая публикация остаётся доступна; новый файл не подменяет данные старого графика.

GET `/projects/{project}/runs/{run}/results`, `/results/{result}` и `/evidence/{artifact}` доступны только в области выбранного проекта/Run. Межзапусковое чтение — через выбор сохранённого Run; автоматический импорт ревизий другой итерации в новый отчёт пока не реализован.

Новые Run фиксируют профили v3. Профили и схемы v1/v2 сохранены для восстановления прежних сессий. Первый renderer не является свободным конструктором страниц: сложные компоновки, страницы команд, дополнительные типы графиков и RAG остаются следующими задачами.

## Проверки

Общая регрессия: 92 теста. Новые сценарии покрывают реальные агрегаты 160000 → 170000 RUB и 6,25%, независимое обнаружение неверного знаменателя, запрет публикации опровергнутого блока, draft/inconclusive, права и идентичность source job, точный хеш проверки, неизменяемость версий, повреждение доказательств, API scope, актуальность данных и resume.

Превью рассчитано на четырёх вымышленных строках. Это проверка исполнения и интерфейса, не бизнес-исследование. Пользовательский ключ не используется, расходов модели нет.
