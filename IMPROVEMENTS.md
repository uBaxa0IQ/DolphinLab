# Улучшение после первого сабмита

Исходный чекпойнт: Git commit 92cc1ac, tag first-submission. Архив отправленной версии сохранён в этом коммите. Рабочая ветка improve-delivery. Ключ .env и датасеты не включены.

Пользователь разрешил дальнейшее улучшение и максимум 350 RUB новых API-расходов. Общий журнал: test-output/improvement-budget-350.json. Не сбрасывать журнал. Учитывать остаточные резервы неизвестных/прерванных запросов как уже занятые деньги. Следующий прогон получает только остаток общего бюджета; не проводить независимые платные вызовы вне журнала.

Текущая гипотеза: провал multiclass был вызван долгим циклом исправления небольших ошибок и чрезмерной сложностью первого кандидата. Предыдущий остановленный запуск не произвёл кандидата: OrdinalEncoder с неверным sparse_output, StratifiedKFold с shuffle=False+random_state и NameError в переменной s. Техлид микроменеджил параметры, вместо быстрого прямого цикла код/результат.

Изменения v1:

- run_python/run_script по умолчанию наблюдают первые 10 секунд и возвращают успешный/ошибочный результат прямо в tool response. Более долгие задания остаются асинхронными. wait_for_seconds 0..30 не ограничивает само исполнение. Нет повторного completion-mail, если результат уже вернулся в инструменте.
- replace_text позволяет точечно исправлять собственный файл. Снимки старых заданий не меняются; менеджерам инструмент недоступен.
- результат и событие содержат реальный script path, stdout/stderr и job_id.
- промпты требуют сначала маленький fit/predict smoke и один честный рабочий baseline; большой CV/поиск — после checkpoint.
- исследование high, сжатие low, без max_tokens/max_completion_tokens.
- Budget has been exceeded / HTTP402 останавливают повторные обращения.

Проверено локально: прежние 31 тест прошли после изменений рантайма, дополнительно прошли inline execution, отсутствие дубля completion, сохранение async-задачи после истечения наблюдения, точечное исправление без изменения frozen code, единый low для compaction во всех параметрах запроса.

Эксперимент 1: test-output/improve-multiclass-v1, чистый multiclass, 1200 сек, high, 6 запросов одновременно, 8CPU/8192MiB локально, предел 100 RUB внутри общего 350. Код прогона в source/. Сохранить результат/аудит и фактическую учтённую стоимость после окончания. При активном прогоне не менять его код и решения. Следом проверять regression или исправлять конкретную причину провала; тратить бюджет только на проверяемые гипотезы.

Кодексовые лимиты: при приближении к исчерпанию сохранить коммит, актуальные PID/пути/стадию/бюджет. После восстановления продолжать с этих файлов, не повторяя уже оплаченные эксперименты. Если цель достигнута, не расходовать остаток бюджета ради самого расхода.
