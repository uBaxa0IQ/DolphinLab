# Sonder workspace

Локальный интерфейс исследовательской платформы. Архивы хакатонных сабмитов и прежний рантайм не изменены.

## Открыть

Из корня репозитория запустить API:

```powershell
.venv\Scripts\python.exe -m uvicorn research_platform.api:app --app-dir apps/api --host 127.0.0.1 --port 8017
```

Во втором терминале:

```powershell
cd apps/web
npm ci
npm run dev
```

Сайт: http://127.0.0.1:5179 . API: http://127.0.0.1:8017/docs . Выбранные порты отличаются от часто используемых 8000/5173, которые были заняты на этом компьютере.

При отдельной установке серверных зависимостей: `python -m pip install -r apps/api/requirements.txt`. Это зависимости приложения, а не список для конкурсной платформы. Текущая локальная среда уже содержит нужные серверные библиотеки. Node.js 22 используется для интерфейса; версии пакетов зафиксированы в `apps/web/package-lock.json`.

## Что доступно

- Два явно помеченных демонстрационных проекта, команды, участники, эксперименты, лента событий и история чата. Данные вымышлены. Ответы в демочате подготовлены заранее; история демочата сохраняется в localStorage браузера.
- Поиск проектов, вкладки, карточки команд и экспериментов, скачивание маркированного демоотчёта, адаптивный чат на небольшом экране.
- Создание собственного проекта через FastAPI, загрузка и скачивание входных файлов, сохранение реальной переписки и дополнительных поручений. После перезагрузки страницы записи читаются из базы.
- Поток SSE с постоянными ID событий и продолжением через Last-Event-ID. Обновления API отражаются в интерфейсе.
- Общий граф агентной сессии LangGraph в `api/research_platform/agent_graph.py`: подготовка контекста → модель → инструменты → продолжение/окончание. Checkpointer и адаптеры передаются явно; граф пока не подключён к веб-серверу.

## Что намеренно выключено

Сервер не загружает корневой `.env`, не создаёт модельного клиента, не вызывает API и не исполняет сгенерированный код. Реальные сообщения имеют состояние `pending`; ответ PM не имитируется. Запуск исследования возвращает явное сообщение, что исполнение отключено. Работающие команды и метрики в демопроектах не являются фактическим прогрессом.

Следующий этап: подключить worker, устойчивый checkpointer, PM и техлида, квитанции инструментов и изолированное выполнение кода. Ранний граф не заменяет существующий рантайм до завершения этой интеграции. PostgreSQL можно выбрать для прикладной базы через DATABASE_URL, но его окружение и миграции ещё не проверены.

## Хранение и режим доступа

По умолчанию SQLite и файлы находятся в игнорируемой `.workspace-data/` в корне репозитория. Файлы имеют UUID-имена, исходное имя — только метаданные, лимит одного файла 100 МБ. ZIP сохраняется как входной файл, автоматически не распаковывается. Исходные данные не коммитятся. Локальный сервер слушает только 127.0.0.1; вход по аккаунтам и публичное размещение ещё не реализованы.

`DATABASE_URL=postgresql+psycopg://...` выбирает PostgreSQL. `WORKSPACE_DATA_DIR` меняет папку хранилища. Сервер читает эти переменные непосредственно из окружения. Пример в `.env.example` — справка, автоматически файл не загружается.

## Проверки этой итерации

По просьбе пользователя автотесты, браузерные сценарии и платные исследования не запускались. Запуск dev-серверов и сборка frontend — техническая подготовка к просмотру, не проверка корректности всей платформы. Фактических результатов AutoML эта итерация не добавляет.
